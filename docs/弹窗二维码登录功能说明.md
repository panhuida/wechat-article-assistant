# 弹窗二维码登录功能说明

## 概述

本功能提供了一种新的微信公众平台登录方式——在 Web 应用中直接弹窗显示二维码，用户扫码后自动完成登录，无需打开 Playwright 浏览器窗口。

## 功能特点

- **无感登录体验**：二维码直接显示在 Web 页面弹窗中，无需切换到外部浏览器窗口
- **后台无头运行**：使用 Playwright headless 模式获取二维码，用户不可见
- **自动状态检测**：登录成功后自动关闭弹窗，继续执行原有操作
- **模式可切换**：支持通过配置在弹窗模式和浏览器模式之间切换

## 配置说明

### 登录模式配置

在 `.env` 文件中配置 `LOGIN_MODE` 参数：

```bash
# 登录方式配置
# popup: 在Web应用中弹窗显示二维码（推荐，不启动可见浏览器）
# browser: 启动Playwright浏览器窗口扫码登录
LOGIN_MODE=popup
```

| 模式 | 值 | 说明 |
|------|-----|------|
| 弹窗模式 | `popup` | 默认值，在 Web 页面中弹窗显示二维码 |
| 浏览器模式 | `browser` | 启动 Playwright 可见浏览器窗口扫码 |

## 技术实现

### 架构设计

```
┌─────────────────────────────────────────────────────────────┐
│                        前端 (Web)                            │
├─────────────────────────────────────────────────────────────┤
│  用户操作 → 需要登录 → 显示二维码弹窗 → 轮询状态 → 登录成功  │
└─────────────────────────────────────────────────────────────┘
                              ↓ ↑
┌─────────────────────────────────────────────────────────────┐
│                      Flask API 层                            │
├─────────────────────────────────────────────────────────────┤
│  /api/wechat/login/qrcode  - 获取二维码                      │
│  /api/wechat/login/poll    - 轮询登录状态                    │
│  /api/wechat/login/cancel  - 取消登录                        │
│  /api/wechat/login/status  - 检查登录状态                    │
└─────────────────────────────────────────────────────────────┘
                              ↓ ↑
┌─────────────────────────────────────────────────────────────┐
│                  WechatAuthenticator                         │
├─────────────────────────────────────────────────────────────┤
│  后台线程运行 Playwright (headless)                          │
│  ↓                                                           │
│  访问微信公众平台 → 截取二维码图片 → 持续轮询页面状态         │
│  ↓                                                           │
│  通过线程安全的共享变量传递状态给主线程                       │
└─────────────────────────────────────────────────────────────┘
```

#### 3. 状态轮询

```python
def poll_login_status(self) -> dict[str, Any]:
    # 只读取共享状态变量，不直接访问 Playwright
    # 避免跨线程访问问题
```

### 线程安全设计

由于 Playwright 对象不能跨线程使用，采用以下设计：

1. **后台线程**：独立运行 Playwright，持续检测登录状态
2. **共享状态变量**：使用 `threading.Lock` 保护状态读写
3. **取消事件**：使用 `threading.Event` 通知后台线程停止

```python
# 线程安全的状态共享
self._login_status_lock = threading.Lock()
self._login_status: dict[str, Any] = {}
self._login_qrcode: str | None = None
self._login_cancel_event = threading.Event()
```

### 二维码获取方式

使用 Playwright 截图方式获取二维码，解决微信防盗链问题：

```python
def _capture_qrcode_from_page(self, page: Page) -> dict[str, Any]:
    # 查找二维码图片元素
    qrcode_element = page.query_selector('img[src*="scanloginqrcode"]')
    
    # 截取元素为图片
    screenshot_bytes = qrcode_element.screenshot()
    
    # 转换为 base64 data URL
    qrcode_base64 = base64.b64encode(screenshot_bytes).decode('utf-8')
    qrcode_data_url = f"data:image/png;base64,{qrcode_base64}"
```

## API 接口说明

### GET /api/wechat/login/qrcode

获取登录二维码。

**响应示例：**

```json
{
    "success": true,
    "status": "waiting",
    "qrcodeUrl": "data:image/png;base64,iVBORw0KGgo...",
    "message": "请使用微信扫描二维码登录"
}
```

**状态说明：**
- `waiting`：等待扫码
- `already_logged_in`：已登录，无需扫码

### GET /api/wechat/login/poll

轮询登录状态。

**响应示例：**

```json
{
    "success": true,
    "status": "scanned",
    "message": "已扫码，请在手机上确认登录"
}
```

**状态说明：**
- `waiting`：等待扫码
- `scanned`：已扫码，等待确认
- `success`：登录成功
- `timeout`：登录超时
- `not_started`：登录未开始

### POST /api/wechat/login/cancel

取消登录流程。

### GET /api/wechat/login/status

检查当前登录状态。

## 前端实现

### 二维码弹窗组件

弹窗组件位于 `base.html` 中，作为全局组件供所有页面使用。

**主要函数：**

| 函数 | 说明 |
|------|------|
| `showQrcodeLoginModal(callback)` | 显示二维码弹窗，登录成功后执行回调 |
| `closeQrcodeModal(skipCancel)` | 关闭弹窗，可选跳过取消请求 |
| `fetchQrcode()` | 获取二维码 |
| `startQrcodePolling()` | 开始轮询登录状态 |
| `stopQrcodePolling()` | 停止轮询 |

### 使用示例

```javascript
// 在需要登录时调用
if (result.needLogin && result.loginMode === 'popup') {
    showQrcodeLoginModal(() => {
        // 登录成功后的回调
        searchAccount();
    });
}
```

## 安全考虑

### 风险对比

| 维度 | 弹窗模式 | 浏览器模式 |
|------|----------|------------|
| 浏览器类型 | Headless 无头 | 正常可见 |
| 指纹检测风险 | 略高 | 低 |
| 用户体验 | 好 | 一般 |

### 建议

1. **控制使用频率**：避免频繁登录/登出
2. **控制 API 调用频率**：这是降低封锁风险的关键
3. **高频使用场景**：建议使用浏览器模式
